1. 概要と用語

iPadOS 向けアプリ。1 枚の画像を取り込み、その色を 彩度・明度・色相 に分けて可視化し、結果を端末内に永続化して後から再度開けるようにする。

用語定義
HSB色相 H（0–360°、赤で始まり赤で終わる）、彩度 S（0–100%）、明度 B（0–100%）。Procreate のカラーパネル「Value」タブと同じ定義。sRGB 成分から計算する。
解析画像取り込んだ画像に EXIF 回転・白合成・sRGB 変換・長辺 4096px 上限の縮小を適用したもの。解析と色相画面の表示・選択はすべてこの画像に対して行う。
グリッド / セル解析画像を長辺 N セル（N = 32 / 64 / 128、既定 64）に分割したもの。棒グラフの棒 1 本がセル 1 個に対応する。
代表色セルを 1 色で表した色。色相は最頻色相法で決め、S/B はセル内全ピクセルの平均。彩度画面の棒の色に使う（明度画面は代表色ではなくセルの明度から作るグレースケールを使う。「3.4 彩度 / 明度 3D 棒グラフ」参照）。
解析（レコード）1 回の取り込みで生成される保存単位。画像コピー・解析結果・メタデータからなる。
無彩色S が 5% 未満の色。色相は未定義として扱う。

2. 画面構成と遷移

  • NavigationSplitView。サイドバー = ライブラリ（保存済み解析の一覧）、詳細 = 解析詳細。
  • 解析詳細はセグメントコントロールで「彩度 / 明度 / 色相」を切り替える。初期表示は「彩度」。
  • 取り込みはサイドバーのツールバー「＋」から始まり、完了すると自動保存されて詳細が開く。
  • iPad のみ、縦横両対応、最小 iPadOS 26.0。UI は日本語。

3.4 彩度 / 明度 3D 棒グラフ

彩度画面と明度画面は同じ 3D ビューを使うが、棒の高さに使う値（彩度 = cell_saturation、明度 = cell_brightness）に加え、棒の色も画面ごとに異なる（BAR-04）。要件 ID の BAR-* は特記なき限り両画面に適用する。

ID要件検証状態
BAR-01グリッドの各セルに棒を 1 本立てる。棒の配置は解析画像内のセル位置と一致させる（左右そのまま、画像の上辺が初期カメラから見て奥）。unit（ジオメトリ）✅
BAR-02棒の高さは値（0–1）に比例し、値 1.0 の高さ = グリッド長辺のセル数 × 0.5（セル幅 = 1 単位）。値 0 でも最大高さの 1% の高さを与える。unit✅
BAR-03棒は正方形断面で、太さはセル幅の 0.8（隙間 20%）。unit✅
BAR-04棒の色は画面ごとに異なる。彩度画面はセルの代表色（cell_color）。明度画面はセルの明度（cell_brightness）に連動した白〜黒のグレースケール（明度 1.0 が白、0.0 が黒。代表色の色相は使わない）。unit✅
BAR-05RealityKit で描画し、全棒を 1 つのメッシュに結合して 1 エンティティで描く。e2e（表示確認）✅
BAR-06床面に解析画像をテクスチャとして貼る。ツールバーのトグルで ON/OFF でき、既定は ON。e2e✅
BAR-071 本指ドラッグでグリッド中心を軸に回転、ピンチでズーム（0.5〜4 倍）。「リセット」で初期カメラ（仰角 45°・方位 30°、グリッド全体が収まる距離）、「俯瞰」で真上からの視点に切り替える。e2e（操作後スクショ） / unit（カメラ計算）✅
BAR-08背景はダークグレー、ライティングは RealityKit 既定。e2e✅
BAR-09画面隅に凡例テキスト「高さ = 彩度 0–100%」（明度画面では「高さ = 明度 0–100%」）を表示する。e2e✅
BAR-10棒タップでの値表示、基準面・目盛り、カラーマップ切替は提供しない。—⏸
BAR-11グリッド奥の角（行0・列0のセル）から対角線上にセル1個分離れた位置に、最大値(100%)のサンプルとなる基準棒を1本表示する。高さは値1.0と同じ（BAR-02 の式）。色は彩度画面が純赤 HSB(0°,100%,100%)、明度画面が白（HSB(なし,0%,100%)、既存のグレースケール規則どおり）。実データの棒と区別するため黒白の破線調ワイヤーフレーム枠を付け、凡例（BAR-09）に「破線枠の棒 = ○○100%の例」を追記する。`grid_width`/`grid_height` やセルデータには含めない描画専用の合成物で、常時表示（トグルなし）。初期カメラのフィット距離にはこの基準棒を含めた余白（extraMargin）を加える。unit（ジオメトリ・カメラ余白） / e2e（表示確認）✅

4. 解析仕様

ID要件検証状態
ANA-01デコード: ImageIO（CGImageSource）で読み、EXIF 回転を適用し、長辺が 4096px を超える場合は 4096px に縮小する。unit✅
ANA-02色の正規化: sRGB 8bit の RGBA に展開し、アルファは白（255,255,255）と合成して不透明にする。unit✅
ANA-03HSB 変換: sRGB 8bit 成分から H ∈ [0,360)、S ∈ [0,1]、B ∈ [0,1] を計算する。B = max(R,G,B)/255、S = (max−min)/max（max = 0 のとき S = 0）。unit✅
ANA-04グリッド分割: 長辺のセル数 N（Core は任意の N ≥ 1 を受け付け、UI は 32/64/128 のみ提示）。画像の長辺が N より小さいときは N = 長辺 px とする。短辺のセル数 = max(1, round(N × 短辺 / 長辺))。セル i のピクセル範囲は [floor(i·W/gridW), floor((i+1)·W/gridW)) とする（高さも同様）。unit✅
ANA-05代表色相（最頻色相法）: セル内で S ≥ 0.05 のピクセルのみを対象に、色相を 5° 刻み 72 ビンへ S を重みとして積む。隣接ビン（±1）を加えて平滑化した値が最大のビンをピークとする。ピーク中心 ±15° に入るピクセルの色相を S 重みで円周平均したものを代表色相とする。unit✅
ANA-06タイブレーク: 平滑化後の値が同じピークが複数あるとき、色相角が小さいビンを選ぶ。unit✅
ANA-07無彩色セル: 対象ピクセルが 0 個のセルは色相未定義とし、代表色は S = 0、B = 平均 B のグレーにする。unit✅
ANA-08セル値: cell_saturation = セル内全ピクセルの S の単純平均、cell_brightness = 同じく B の単純平均。代表色 = HSB(代表色相, cell_saturation, cell_brightness) を sRGB 8bit に変換したもの（四捨五入）。unit✅
ANA-09解析は決定的であること。同じ入力と N に対して常に同じ結果を返す。unit✅
ANA-10解析はキャンセル可能であること（Task のキャンセルに応答する）。unit✅

平均色（sRGB 平均・リニア光平均）で代表色を決める方式は、混色によって元画像に存在しない色相を生むため採用しない。円周平均のみの方式も二色セルで中間色相を生むため採用しない。

5. 永続化仕様

ID要件検証状態
PER-01SQLite を Documents/color-scheme-analyzer.sqlite に置き、GRDB.swift でアクセスする。マイグレーションは GRDB の DatabaseMigrator で管理する。iCloud は使わない。unit✅
PER-02元画像はバイト列を再エンコードせず Documents/images/<UUID>.<拡張子> にコピーする。拡張子は元ファイルの UTType から決める。unit✅

PER-05再解析は image_path の画像から計算し、同じ行の grid_*・cell_*・analysis_version を上書きする。unit✅
PER-06削除は DB 行と画像ファイルの両方を消す。ファイルが既にない場合もエラーにしない。unit✅
PER-07analysis_version が現行と異なる解析を開いたとき、自動では再解析せず、詳細画面に「解析方式が更新されています。再解析できます」と表示する。e2e / unit✅

6.5 実写フィクスチャ

手続き生成した画像だけでは細部の階調やノイズを再現できないため、著作権上クリアな実写を 1 枚置く（starry-night.png: Vincent van Gogh, The Starry Night, 1889。パブリックドメイン、出典は App/ColorSchemeAnalyzer/Fixtures/ATTRIBUTION.md、取得は scripts/fetch-painting-fixture.sh）。これは E2E の表示確認とスクリーンショット用で、期待値は「例外なく解析が完了し、各画面が表示される」ことのみ（ImportFlowUITests.testRealPaintingFixtureCompletesAndDisplaysAllTabs）。風景・人物など他の実写カテゴリを追加する場合も、パブリックドメインまたは CC0 など再配布可能なライセンスの画像に限る。

8. 検証基盤

  • Core: Packages/ColorSchemeCore（ターゲット ColorAnalysis / ImageDecoding / Persistence）。Swift Testing で swift test。6.1〜6.4 の期待値をそのままテストの期待値に使う。

  • アクセシビリティ識別子（E2E の契約）: ライブラリ library.list / library.row / library.addButton / library.emptyState / library.confirmDelete / library.renameField / library.renameSave、 取り込み import.fromPhotos / import.fromFiles / import.resolution.picker（セグメント 32・64・128）/ import.resolution.start / import.resolution.cancel / import.progress / import.progress.cancel、 詳細 detail.segment / detail.reanalyze / detail.emptyState / detail.versionBanner、 3D bar.view / bar.floorToggle / bar.reset / bar.topDown / bar.legend、 色相 hue.image / hue.hint / hue.marker / hue.wheel / hue.wheel.marker / hue.readout（文言例「H 240° S 50% B 100%」「無彩色 S 0% B 73%」）/ hue.swatch。

  • E2E で自動化しない操作: 2 本指パン（XCUITest に API がない。ピンチは自動化する）、Apple Pencil、実機。
  • Makefile: make gen（XcodeGen）、make test-core、make test-ui。
